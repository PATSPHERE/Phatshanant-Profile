Prompt Starter Library

Prompt สำเร็จรูปสำหรับเริ่มงานได้เร็วขึ้น เลือกตาม “งานที่ต้องทำ” แล้ว Copy ไปใช้ได้ทันที จากนั้นเติมข้อมูลจริง บริบท และข้อจำกัดของงานคุณก่อนใช้งาน

💡
RELEARN TIP

Prompt สำเร็จรูปคือ “จุดเริ่มต้น” ไม่ใช่คำตอบตายตัว ถ้างานมีข้อมูลเฉพาะหรือมีความเสี่ยง ให้เติมบริบท ข้อจำกัด และตรวจผลลัพธ์ก่อนใช้จริงเสมอ

Email & Message

อ่าน • สรุป • ร่างตอบ • ดึงสิ่งที่ต้องทำ

E1

สรุปอีเมลให้จับใจความเร็ว

SUMMARY

ใช้เมื่ออีเมลยาวและต้องรู้ว่า “ประเด็นไหนสำคัญ / ต้องทำอะไรต่อ”

ช่วยสรุปอีเมลต่อไปนี้เป็น 5 ส่วน: 1) ประเด็นสำคัญ 2) สิ่งที่ผู้ส่งต้องการ 3) เรื่องเร่งด่วน 4) สิ่งที่ฉันต้องทำต่อ 5) คำถามที่ยังต้องตอบ อีเมล: [วางอีเมลที่นี่] ห้ามเพิ่มข้อมูลที่ไม่มีในต้นฉบับ
E2

ร่างอีเมลตอบแบบสุภาพ

DRAFT REPLY

ใช้เมื่อรู้ใจความแล้ว แต่อยากได้ร่างคำตอบที่มืออาชีพ

ช่วยร่างอีเมลตอบกลับจากข้อมูลด้านล่าง บริบท: [อธิบายสถานการณ์สั้น ๆ] สิ่งที่ต้องตอบ: [ใส่ประเด็น] โทนภาษา: สุภาพ ชัดเจน กระชับ ข้อจำกัด: อย่ารับปากสิ่งที่ยังยืนยันไม่ได้ และอย่าเพิ่มข้อมูลที่ไม่มี ขอหัวข้ออีเมล + เนื้อหาอีเมลพร้อมใช้
E3

ดึง Action Items จากอีเมล

ACTION

ใช้เมื่ออีเมลมีหลายเรื่องและต้องแปลงเป็นรายการติดตาม

จากอีเมลนี้ ช่วยดึงเฉพาะงานที่ต้องดำเนินการต่อ แล้วจัดเป็นตาราง: - Task - Owner - Deadline - Status - ข้อมูลที่ยังขาด ถ้าไม่มี Owner หรือ Deadline ให้ใส่ “ยังไม่ระบุ” ห้ามเดา อีเมล: [วางอีเมล]

Meeting & Action

Agenda • Summary • Decision • Action Items

M1

สร้าง Agenda ก่อนประชุม

AGENDA

ใช้เมื่อมีข้อมูลหลายประเด็นและต้องการจัดลำดับการประชุม

ช่วยจัด Agenda การประชุมจากข้อมูลต่อไปนี้ วัตถุประสงค์การประชุม: [ใส่เป้าหมาย] ประเด็นที่ต้องคุย: [วางรายการ] เวลาประชุมทั้งหมด: [เช่น 60 นาที] จัดลำดับ Agenda พร้อมเวลาต่อหัวข้อ และระบุว่าแต่ละหัวข้อต้องการ “แจ้งให้ทราบ / หารือ / ตัดสินใจ”
M2

สรุปประชุมแบบผู้บริหาร

MEETING SUMMARY

ใช้เมื่อมี Meeting Note ยาว แต่ต้องการสาระที่ใช้ติดตามงานได้ทันที

ช่วยสรุปบันทึกประชุมนี้เป็น 4 ส่วน: 1) Key Discussion 2) Decisions / มติ 3) Action Items 4) Issues ที่ยังต้องติดตาม สำหรับ Action Items ให้ทำตาราง: Task | Owner | Deadline | Status ห้ามเดาข้อมูลที่ไม่มีในบันทึก Meeting Note: [วางบันทึกประชุม]
M3

Meeting Note → To-do

TO-DO

ตรงกับ flow ที่สอนใน Section 3: Task • Owner • Deadline • Status

เปลี่ยนบันทึกประชุมต่อไปนี้เป็น To-do List โดยแสดง: - Task - Owner - Deadline - Status - Dependency / งานที่ต้องรอก่อน (ถ้ามี) ถ้าไม่มีข้อมูล ให้ใส่ “ยังไม่ระบุ” และห้ามสร้าง Owner หรือ Deadline ขึ้นเอง บันทึกประชุม: [วางข้อมูล]

Excel / Data

Trend • Anomaly • Insight • Management View

D1

อ่านตารางหา Insight

DATA INSIGHT

ใช้กับ Excel/CSV เมื่อต้องการมากกว่าการ “เล่าตัวเลขกลับมา”

วิเคราะห์ข้อมูลในไฟล์/ตารางนี้ แล้วสรุป: 1) แนวโน้มสำคัญ 2) จุดผิดปกติ 3) รายการ/พื้นที่ที่เกิดซ้ำ 4) สิ่งที่ควรถามต่อ 5) ข้อมูลที่ยังขาด 6) Next Step สำหรับผู้จัดการ อ้างอิงเฉพาะข้อมูลที่มี ถ้าไม่พอให้บอกตรง ๆ ว่าขาดอะไร
D2

สรุป KPI สำหรับผู้บริหาร

EXECUTIVE SUMMARY

ใช้เมื่อมีตารางหลายคอลัมน์และต้องการ Management View

จากข้อมูลนี้ ช่วยทำ Executive Summary สำหรับผู้บริหาร โดยแสดง: - KPI หลัก - สิ่งที่ดีขึ้น / แย่ลง - จุดที่ต้องเฝ้าระวัง - สาเหตุที่ “ข้อมูลบอกได้” เท่านั้น - 3 คำถามสำคัญก่อนตัดสินใจ สรุปไม่เกิน 1 หน้า และห้ามสรุปเกินหลักฐานในข้อมูล
D3

เตรียม Data → PowerPoint

PRESENTATION

ใช้เป็นจุดเริ่มต้นก่อน Use Case ช่วง Apply: Excel → Presentation

จากข้อมูลในไฟล์นี้ ช่วยเสนอ Storyline สำหรับ PowerPoint จำนวน [X] หน้า แต่ละหน้าให้ระบุ: - ชื่อสไลด์ - Key Message 1 ประโยค - ตัวเลข/ข้อมูลที่ควรแสดง - กราฟหรือตารางที่เหมาะ - ข้อสังเกตที่ต้องให้มนุษย์ตรวจ ใช้เฉพาะข้อมูลจากไฟล์ ห้ามสร้างตัวเลขใหม่

Document & Knowledge

อ่าน • จัดโครง • ถามจากเอกสาร • สังเคราะห์

K1

สรุปเอกสารยาว

LONG DOCUMENT

เหมาะกับรายงาน คู่มือ ข้อเสนอ หรือเอกสารหลายหน้า

ช่วยสรุปเอกสารนี้เป็น: 1) วัตถุประสงค์ 2) ประเด็นสำคัญ 3) ข้อกำหนด/เงื่อนไข 4) ความเสี่ยงหรือข้อควรระวัง 5) สิ่งที่ต้องตัดสินใจ 6) คำถามที่ควรถามต่อ ถ้ามีข้อความที่ไม่ชัด ให้ระบุว่า “ต้องตรวจต้นฉบับเพิ่มเติม”
K2

ถามจากเอกสารเท่านั้น

SOURCE-GROUNDED

แนวเดียวกับ NotebookLM / Knowledge Base

ตอบคำถามของฉันโดยใช้ “เฉพาะเอกสารที่แนบ” เท่านั้น ทุกคำตอบต้อง: - ระบุว่าพบข้อมูลจากส่วนไหน - ถ้าเอกสารไม่มีคำตอบ ให้ตอบว่า “ไม่พบข้อมูลในเอกสาร” - ห้ามใช้ความรู้ภายนอกมาปะปน คำถาม: [ใส่คำถาม]
K3

จัดโครงสร้างเอกสาร

STRUCTURE

ใช้เมื่อต้องอ่านหลายประเด็นแล้วอยากเห็น Framework ที่ชัดขึ้น

อ่านเอกสารนี้แล้วช่วยจัดโครงสร้างใหม่ โดยแยกเป็น: - Facts - Issues - Decisions - Risks - Actions - Open Questions คงสาระเดิม ไม่ตัดข้อมูลสำคัญ และไม่เพิ่มข้อสรุปที่เอกสารไม่ได้กล่าวไว้

Compare & Decide

เปรียบเทียบ • หา Trade-off • เตรียมการตัดสินใจ

C1

เปรียบเทียบ 2–3 ตัวเลือก

COMPARE

ใช้กับ Vendor, Proposal, Solution หรือทางเลือกที่ต้องตัดสินใจ

ช่วยเปรียบเทียบตัวเลือกต่อไปนี้โดยใช้เกณฑ์: - ประโยชน์ - ข้อจำกัด - ความเสี่ยง - งบประมาณ/ทรัพยากร - ความง่ายในการนำไปใช้ - สิ่งที่ยังต้องตรวจ ทำเป็นตาราง และสรุปท้ายว่า “แต่ละตัวเลือกเหมาะเมื่อใด” อย่าตัดสินแทนถ้าข้อมูลยังไม่พอ
C2

หา Gap ก่อนตัดสินใจ

GAP CHECK

ใช้เมื่อข้อเสนอหรือข้อมูลดูดี แต่ยังไม่แน่ใจว่าขาดอะไร

จากข้อมูล/ข้อเสนอนี้ ช่วยแยกเป็น: 1) สิ่งที่ชัดเจนแล้ว 2) สิ่งที่ยังไม่ชัด 3) สมมติฐานที่ซ่อนอยู่ 4) ความเสี่ยง 5) ข้อมูลที่ต้องขอเพิ่ม 6) 5 คำถามที่ควรถามก่อนตัดสินใจ อย่าคาดเดาข้อมูลที่ไม่มี

Plan & Brainstorm

วางแผน • ระดมไอเดีย • แปลงไอเดียเป็นงาน

P1

ทำ Work Plan

PLAN

ใช้เมื่อมีเป้าหมายแต่ยังไม่ได้แตกเป็นขั้นตอน

ช่วยทำ Work Plan จากเป้าหมายนี้: [ใส่เป้าหมาย] จัดเป็นตาราง: Step | Outcome | Owner | Timeline | Dependency | Risk | Checkpoint ถ้าข้อมูลส่วนไหนยังไม่มี ให้เว้นเป็น “ต้องกำหนด” แทนการเดา
P2

Brainstorm แบบมีกรอบ

IDEATION

ใช้เมื่อต้องการไอเดีย แต่ไม่อยากได้คำตอบกว้างจนเลือกไม่ได้

ช่วยเสนอไอเดียจำนวน 10 แนวทางสำหรับ: [ใส่โจทย์] ข้อจำกัด: [งบประมาณ / เวลา / กลุ่มเป้าหมาย / สิ่งที่ห้าม] จัดไอเดียเป็น 3 กลุ่ม: - ทำได้ทันที - ต้องเตรียมเพิ่ม - ไอเดียทดลอง ท้ายสุดเลือก 3 ไอเดียที่ควรพิจารณาต่อ พร้อมเหตุผล

Rewrite & Tone

ปรับภาษา • ความยาว • น้ำเสียง โดยไม่เปลี่ยนสาระ

R1

ปรับให้สุภาพและกระชับ

REWRITE

ใช้กับอีเมล ข้อความประกาศ หรือข้อความถึงลูกค้า

ช่วยปรับข้อความต่อไปนี้ให้: - สุภาพ - กระชับ - อ่านง่าย - ไม่แข็งหรือเป็นทางการเกินไป คงความหมายเดิมทุกประเด็น และอย่าเพิ่มคำรับปากหรือข้อเท็จจริงใหม่ ข้อความ: [วางข้อความ]
R2

ปรับตามผู้รับ

AUDIENCE

ใช้เมื่อข้อความเดียวกันต้องสื่อสารกับคนละกลุ่ม

ช่วยปรับข้อความนี้ให้เหมาะกับผู้รับ: [เช่น ผู้บริหาร / ลูกบ้าน / ทีมงาน / คู่ค้า] ต้องการโทน: [สุภาพ / เป็นมิตร / กระชับ / มั่นใจ] คงสาระและข้อเท็จจริงเดิมทุกประการ จากนั้นอธิบายสั้น ๆ 3 ข้อว่าคุณปรับอะไรและเพราะอะไร

Research & Ask Further

หาคำถามต่อ • ระบุสิ่งที่รู้/ไม่รู้ • ลดการสรุปเร็วเกินไป

Q1

รู้แล้ว / ยังไม่รู้

RESEARCH FRAME

ใช้ก่อนทำ Research หรือก่อนตัดสินใจจากข้อมูลไม่ครบ

จากข้อมูลนี้ ช่วยแยกเป็น 4 ส่วน: 1) สิ่งที่เรารู้แล้ว 2) สิ่งที่ยังไม่รู้ 3) ข้อมูลที่ควรหาเพิ่ม 4) คำถามสำคัญ 10 ข้อที่ควรถามต่อ อย่าตอบคำถามที่ข้อมูลปัจจุบันยังรองรับไม่ได้
Q2

Red Team คำตอบ

CHALLENGE

ใช้ตรวจไอเดีย แผน หรือข้อสรุปก่อนนำไปใช้จริง

ช่วยทำ Red Team กับข้อเสนอนี้ โดยตรวจ: - สมมติฐานที่อาจผิด - ข้อมูลที่ยังขาด - ความเสี่ยง - ผลกระทบที่อาจไม่ได้ตั้งใจ - มุมมองของผู้มีส่วนได้ส่วนเสียที่อาจไม่เห็นด้วย - 5 คำถามที่ควรตอบให้ได้ก่อนเดินหน้าต่อ อย่าวิจารณ์เพื่อค้านอย่างเดียว ให้เสนอวิธีลดความเสี่ยงด้วย

Human Check ก่อนนำ Prompt หรือ Output ไปใช้จริง

Factข้อมูลและข้อเท็จจริงถูกต้องหรือไม่
Privacyมีข้อมูลส่วนบุคคล/ข้อมูลลับหรือไม่
Contextเหมาะกับสถานการณ์และผู้รับหรือไม่
