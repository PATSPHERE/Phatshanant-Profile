# RELEARN OS — Brand & Production Guide

Status: **LOCKED working rules for the RELEARN OS Learning Hub**

This file governs all public-facing assets produced inside `relearn-os-learning-hub/`.

## 1. Brand First

Every learner-facing asset is a brand touchpoint. Before publishing, confirm that the asset clearly represents RELEARN OS through:
- official logo
- approved blue–cyan–green visual language
- consistent typography hierarchy
- RELEARN OS mascot usage where appropriate
- consistent footer / section identity
- clear, useful learner experience

Do not treat branding as decoration added after content.

## 2. Source of Truth

When a Master or LOCKED asset exists, **reuse it**. Do not redesign it, reinterpret it, or create a substitute.

Priority order:
1. Latest LOCKED / approved Master asset
2. Latest approved section content / Master Presentation
3. Existing approved Learning Hub component
4. New production only when no approved asset exists

If the required master asset is unavailable, **omit it temporarily rather than inventing a replacement**.

## 3. Official Logo

Use the official RELEARN OS logo file. Do not recreate the wordmark with typed text.

Current public logo asset:
`../ai-business-transformation-academy/assets/relearnos-logo.png`

Logo position, scale and whitespace should remain consistent across a document family.

## 4. Mascot Rules

The RELEARN OS mascot is a fixed brand character.

Rules:
- use the approved Master Mascot only
- reuse approved Sticker / pose library before generating a new pose
- crop / scale / place as needed, but do not reinterpret character identity
- use mascot by function: Guide / Tip / Think / Warning / Human Check / Celebrate
- avoid multiple mascots on one page unless each has a clear role
- never use a letter, emoji, generic robot, or placeholder as a mascot substitute
- if the official mascot asset is not available in the repo, leave the mascot area empty until the correct asset is added

## 5. Visual Language

Core visual DNA:
- white / soft-blue airy background
- Royal Blue as main brand color
- cyan / teal / green accents
- rounded cards
- soft depth, not heavy shadows
- blue–cyan–green curve / ribbon language where suitable
- Thai-first hierarchy
- fresh, bright, modern, professional
- variety by content type without breaking brand consistency

Do not make every page identical. Keep the **frame consistent** and allow the **content layout to adapt**.

## 6. Downloadable Document System

For Playbooks / Worksheets / Quick Guides / PDF resources:

### LOCKED
- official logo zone
- header / section label
- grid and margin logic
- typography hierarchy
- footer / page number system
- brand colors
- RELEARN OS visual DNA

### EDITABLE
- page count
- content layout
- number of cards / columns
- worksheet structure
- prompt examples
- mascot pose / crop
- tip / warning placement

Page count follows content. Do not force every resource into the same number of pages.

Principle:
**Minimum Complete Resource** — use the fewest pages that still let the learner understand and use the topic independently.

## 7. Learning Experience Roles

Different assets have different jobs:

- **Slide** = teach
- **HTML / Guided Demo** = demonstrate / interact
- **Playbook / PDF** = learn, review, keep
- **Prompt Starter Library** = pick and use immediately
- **Interactive Builder** = practice and create
- **Learning Hub** = umbrella access point for all section resources
- **LINE OA** = post-class access / support layer; do not design LINE UX before Learning Hub assets are complete

## 8. Section 3A Locked Architecture

Section 3A contains three distinct assets:

1. **3A Prompt Playbook**
   - learning / review asset
   - 4-page branded playbook
   - printable / saveable
2. **Prompt Starter Library**
   - ready-to-use prompts by job
   - copy and use
3. **Interactive Prompt Builder**
   - 4-field prompt scaffold
   - practice and generate

Do not merge these into one oversized asset.

## 9. Prompt Content Rules

Prompt Starter Library must:
- trace back to concepts taught in the approved Master Slide
- become more detailed and practical than the slide
- be organized by real work task
- be Thai-first
- use English labels only where useful for UI familiarity
- be copy-ready
- include placeholders where the learner must add context
- avoid inventing facts, owners, deadlines or source information

## 10. Production Workflow

For every new RELEARN OS asset:

**Approved Master Content → Select Existing Template → Adapt Content Layout → Apply Brand Assets → UX Check → QA → Publish**

Before creating something new, check whether an approved component already exists.

## 11. Pre-flight QA

Before publishing, verify:
- correct Master content source
- official logo, not typed substitute
- correct mascot or no mascot
- no invented brand elements
- readable on mobile
- printable when intended
- no duplicate/conflicting download path
- resource is in the correct Section
- wording matches the role of the asset
- customer can understand what to do next
- asset clearly looks and feels like RELEARN OS

## 12. Public vs Internal

This repository is for learner-facing / public resources.

Do **not** place confidential curriculum architecture, internal methods, private client materials, speaker notes, internal QA logic, or editable source masters here unless intentionally approved for public release.

Internal production systems should live in a separate private repository.

---
**Working principle:** Every asset is a Brand Moment. Use it to reinforce RELEARN OS consistently, clearly and usefully.
